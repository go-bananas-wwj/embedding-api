# 自定义训练多类别问题修复计划

## 一、这次只改什么

只修改自定义模型训练中的两种训练方式：

1. **传统方法**：使用 Sentinel-2 图像特征训练 Random Forest。
2. **DINOv3 方法**：使用 DINOv3-SAT493M 特征训练下游 MLP。

以下内容本次不改：

- 前端提交 `/models` 的参数格式。
- 玄女 embedding 的训练。
- AEF 的训练。
- 系统预设模型。
- 单个 Patch 推理和批量推理的接口地址。

前端仍然只需要提交类别列表和每个类别的 Polygon，不需要增加新参数。

## 二、现在为什么会报错

目前后端处理多个类别时，实际是把它们拆开训练：

- 水体训练一个二分类头。
- 建筑物训练一个二分类头。
- 道路再训练一个二分类头。
- 最后把这些头放进同一个自定义模型。

这个思路本身没有问题，问题出在训练数据转换上。

### 1. DINOv3 的问题

DINOv3 最终使用的特征图只有 `14×14`。

前端画的小 Polygon 原本可能只覆盖几个像素。当前代码直接把标注缩小到 `14×14`，小标注可能缩完以后一个像素都不剩，于是后端认为这个类别没有训练样本。

真实请求中：

- 水体标注原来只有 2 个有效标注像素。
- 建筑物标注原来只有 5 个有效标注像素。
- 缩到 `14×14` 后，两者都变成了 0。

所以出现：

`No valid dinov3_sat493m embedding samples`

### 2. 传统方法的问题

传统方法使用 Sentinel-2 图像。部分前端 Polygon 对应的位置，在 Sentinel-2 图像中可能是黑边、无数据区域或者无效像素。

当前代码只发现“没有训练样本”，但没有告诉用户：

- 是哪个类别失败。
- 是哪个 Patch 失败。
- 是哪个月份失败。
- 是没有图像，还是 Polygon 落在无效区域。

所以出现：

`No valid training polygons overlap available Sentinel-2 pixels`

### 3. 多类别共同存在的问题

当前多个类别训练时反复使用同一个模型文件。后一个类别可能覆盖前一个类别的临时结果。

如果中间某个类别失败：

- 整个训练任务直接失败。
- 已成功训练的类别可能留下不完整文件。
- 错误信息只显示笼统原因，不知道具体是哪个类别。

## 三、准备怎么修改

## 第一步：按类别独立整理训练数据

后端收到多个类别后，先按照 `class_id` 分组。

例如前端提交：

- 水体：2 个 Polygon。
- 建筑物：3 个 Polygon。
- 道路：0 个 Polygon。

后端处理为：

- 水体单独训练一个头。
- 建筑物单独训练一个头。
- 道路因为没有任何标注，不训练。

这里仍然遵循之前确定的规则：

- 类别出现在 `classes` 中，但没有 Polygon：自动忽略。
- 类别只要存在 Polygon：必须训练，不能静默丢掉。

## 第二步：修复传统方法的标注对齐

传统方法不再先生成固定大小的标注图再缩放。

新的处理流程：

1. 找到 Polygon 对应的 Sentinel-2 图像。
2. 读取图像真实的坐标系、范围和像素大小。
3. 将 WGS84 Polygon 直接投影到这张 Sentinel-2 图像的像素网格。
4. 统计 Polygon 覆盖了多少有效像素。
5. 使用有效像素训练该类别的 Random Forest 二分类头。

如果 Polygon 完全落在无效区域，则不再返回一句模糊的英文，而是明确说明：

> 类别“水体”在 `haidian/patch_000035/202604` 的 Sentinel-2 有效像素覆盖为 0，无法训练。请检查该月份影像或更换标注位置。

传统方法的模型结构不变，仍然是：

- 一个类别一个 Random Forest。
- 多个类别最终组合为一个自定义模型。

## 第三步：修复 DINOv3 的小标注消失

DINOv3 仍然使用 `14×14` 特征图，但不再用简单的最近邻缩放标注。

新的处理方式：

1. 先保留前端 Polygon 在原始图像中的真实范围。
2. 计算每个 DINOv3 token 格子与 Polygon 的实际重叠面积。
3. 只要一个格子与 Polygon 有足够的真实重叠，就把它作为正样本。
4. 不使用随意膨胀，不把 Polygon 外面的大片区域伪造成正样本。

这样可以解决：

- 小建筑缩完消失。
- 细道路缩完断掉。
- 小水体缩完变成 0 个像素。

如果 Polygon 实在太小，连一个 DINO token 都无法可靠表达，则返回明确提示，而不是继续训练出一个错误模型。

DINOv3 的模型结构也保持不变：

- DINOv3-SAT493M 只负责提取冻结特征。
- 每个类别训练一个独立 MLP 二分类头。
- 多个类别最终组合成一个自定义模型。

## 第四步：每个类别使用独立临时文件

训练过程中，每个类别先保存到自己的临时文件，例如：

```text
model_xxx/
  water.pkl
  building.pkl
  road.pkl
```

只有全部有标注的类别都训练成功后，才把它们打包成最终模型。

这样可以保证：

- 不会发生类别之间互相覆盖。
- 某个类别失败时，不会发布残缺模型。
- 已经在线使用的旧模型不会被失败的重训练破坏。

最终前端看到的仍然只有一个 `model_id`，不需要分别管理这些类别头。

## 第五步：把报错信息写清楚

训练失败时，任务详情增加以下信息：

- 失败的类别 ID 和类别名称。
- Patch ID。
- 月份。
- 使用的是传统方法还是 DINOv3。
- 原始 Polygon 覆盖像素数。
- 转换到训练特征后剩余的有效像素数。
- 失败的具体原因。

例如：

```json
{
  "status": "failed",
  "error_code": "NO_VALID_SOURCE_PIXELS",
  "message": "类别“水体”没有可用于训练的 Sentinel-2 有效像素",
  "class_id": "cls_000",
  "class_name": "水体",
  "patch_id": "patch_000035",
  "month": "202604",
  "polygon_pixels": 2,
  "valid_training_pixels": 0
}
```

`POST /models` 仍然是异步接口，前端请求方式不变，只是后续查询任务时能看到更清楚的原因。

## 四、怎么测试

### 1. 传统方法

分别测试：

- 一个类别、一个 Polygon。
- 两个类别，每个类别一个 Polygon。
- 三个类别，每个类别多个 Polygon。
- 类别已声明但没有 Polygon。
- Polygon 落在 Sentinel-2 有效区域。
- Polygon 落在无数据区域。
- 某个月份没有 Sentinel-2 图像。

检查结果：

- 有效类别都生成独立 Random Forest 头。
- 没有标注的类别自动忽略。
- 无效数据返回明确中文错误。
- 不产生残缺模型。

### 2. DINOv3

分别测试：

- 小建筑 Polygon。
- 细道路 Polygon。
- 小水体 Polygon。
- 两个及以上类别同时训练。
- Polygon 越界。
- DINOv3 特征缺失。

检查结果：

- 小 Polygon 投影到 `14×14` 后不再无故消失。
- 每个类别都生成独立 MLP 头。
- 多类别模型能够正常完成训练。

### 3. 推理测试

对两种训练方式都测试：

- `/models/{model_id}/infer`
- `/models/{model_id}/infer_batch`

检查：

- 一个模型 ID 可以同时输出多个训练类别。
- 每个类别使用前端提交的颜色。
- 批量推理与单 Patch 推理结果一致。
- 推理仍然读取训练时绑定的传统特征或 DINOv3 特征，不会错误切换到玄女 embedding。

## 五、最终验收标准

修改完成后需要满足：

1. 传统方法可以训练两个及以上类别。
2. DINOv3 可以训练两个及以上类别。
3. 每个有 Polygon 的类别都有独立二分类头。
4. 没有 Polygon 的类别不会参与训练。
5. DINOv3 的小 Polygon 不会因为缩放直接消失。
6. 传统方法能正确判断 Polygon 与 Sentinel-2 有效像素的重叠。
7. 任意类别失败时，不生成可用状态的残缺模型。
8. 错误信息能直接看出类别、Patch、月份和失败原因。
9. 前端 API 请求格式完全不变。
10. 单 Patch 推理和批量推理都能正常使用多类别模型。

## 六、预计修改的文件

主要修改：

- `app/routers/models.py`：多类别拆分、训练和最终打包。
- `app/services/training_engine.py`：传统方法和 DINOv3 的训练处理。
- `app/services/geojson_adapter.py`：Polygon 与训练网格的对齐。
- `app/services/s2_ml.py`：传统 Sentinel-2 特征和有效像素处理。
- `app/services/external_embeddings.py`：DINOv3 token 网格信息。

测试修改：

- `tests/test_models.py`
- `tests/test_training_engine.py`
- `tests/test_inference_engine.py`

文档只补充这两种自定义训练方式的多类别说明，不改其他接口文档。
